# 1. Project and Learning Overview

## What I was trying to achieve

The evident goal was to convert a Figma-designed canteen billing/ordering product — initially framed around TASL canteen bill management and mobile payment flow — into a working software artifact, while also addressing backend data/API needs.

The broader project arc included:
- Converting Figma exports into frontend code.
- Handling Figma JSON structure, styling, text, images, positioning.
- Choosing frontend stack: React Native, Vite+React PWA, CRA+React PWA, React+Tailwind.
- Setting up backend/data options: Airtable, Supabase, custom API/SQL.
- Debugging Windows/Node/PowerShell environment.
- Building a renderer that could map Figma design data to UI.
- Exposing app for mobile testing via tunnel.
- Considering PWA vs native mobile.

## Unfamiliar challenges encountered

The user repeatedly encountered unfamiliar territory:
- Figma JSON was deeply nested: `document → children → CANVAS → FRAME → elements`, using `absoluteBoundingBox`, `fills`, `strokes`, `characters`, `imageRef`.
- No responsive layout hints; absolute coordinates only.
- Image fills required separate Figma API calls.
- Interaction states not present in JSON.
- Initial React Native attempt incompatible with browser runtime.
- Node/npm not recognized on Windows.
- Module system ambiguity: CommonJS vs ESM.
- Backend choice ambiguity: Airtable vs Supabase vs custom SQL/API.
- Mobile access: localhost not reachable from physical device.

## How capability developed through the work

The evidence suggests a learning trajectory:
- From **no working app / no clear starting point** → to **running Vite PWA / CRA PWA**.
- From **JSX SyntaxError** → to **recursive renderer built**.
- From **Figma JSON mismatch** → to **renderer mapping fixed**.
- From **MODULE_TYPELESS_PACKAGE_JSON confusion** → to **user deciding on `"type": "module"`**.
- From **backend ambiguity** → to **Supabase/PostgreSQL/SQL design decisions**.
- From **AI-following in some sessions** → to **user-driven diagnosis in later sessions**.

But this is not a story of seamless mastery. It is a story of progressive clarity through confusion, testing, failure, and correction.

# 2. Strongest Engineering Episodes

## Episode 1: From “App.js should run” to verified frontend rendering

**Sources:** S5-1, S5-3, S5-4, S5-6

**User’s goal:** Run a Figma-derived app.

**Unfamiliar problem:** User attempted to run `App.js` directly with Node.js and hit `SyntaxError: Unexpected token '<'`. This indicated JSX was not being transpiled.

**User’s actions/decisions:**
- Accepted pivot from React Native to Vite+React PWA for faster visual iteration.
- Built `FigmaRenderer.jsx` through versions:
  1. Basic TEXT/RECTANGLE.
  2. Recursive `absoluteBoundingBox` positioning.
  3. Defensive defaults + RGBA conversion.
  4. Image placeholder.
- Fixed `designData.map is not a function` by diagnosing nested-object vs flat-array mismatch.
- Corrected extraction path to `document.children[0].children[0].children`.
- Rewrote recursive renderer mapping `fills→backgroundColor`, `strokes→border`, `absoluteBoundingBox→absolute positioning`.

**Verified outcome:**
- Vite+React PWA ran at `localhost:5173`.
- First frame rendered logo rectangle, “Profile” text, hamburger frame, rounded button.
- CRA PWA compiled successfully at `localhost:3002`.
- React app rendered frames, rectangles, text with positioning/colors.

**Why this is strong:** Root-cause debugging, recursive algorithm design, defensive rendering.

## Episode 2: Build-error cascade and module-system clarity

**Sources:** S5-1, S5-5

**User’s goal:** Get Node script running and understand module behavior.

**Unfamiliar problem:** Multiple build errors:
- Missing `start` script.
- CSS-in-JS Babel error.
- React 17 vs 18 API mismatch.
- ESM extension requirements.
- Dynamic JSON import failure.

Then later:
- `MODULE_TYPELESS_PACKAGE_JSON` warning.
- User asked whether `"type": "module"` was permanent or temporary.
- User asked about `.mjs`/`.cjs` dual-module strategy.
- User chose simpler permanent config first.

**User’s reasoning/actions:**
- Systematically fixed five compilation errors.
- Investigated module warning rather than ignoring it.
- Shared `package.json` contents for precise diagnosis.
- Learned CommonJS vs ESM distinction.

**Verified outcome:** `MODULE_TYPELESS_PACKAGE_JSON` warning resolved after adding `"type": "module"`.

**Why this is strong:** Technical judgment, patience, willingness to understand before choosing.

## Episode 3: Backend/data-model decision-making

**Sources:** S5-2, S5-4

**User’s goal:** Support canteen billing data/API.

**Unfamiliar problem:** How to model employee, order, payment relationships.

**Options considered:**
- Airtable linked records + Lookup/Rollup.
- Direct API filtering via `FILTER_BY_FORMULA`.
- Standalone SQL backend: Supabase PostgreSQL with auto-generated REST API; custom API on Railway/Render/db4free.

**User’s decision:** Selected Supabase for PostgreSQL + auto-generated REST API as lowest-code backend option. Kept Airtable linked records as alternative.

**User’s technical actions:**
- Drafted Airtable schema.
- Wrote parameterized SQL for Supabase.
- Addressed NOT NULL constraints.
- Defined defaults.
- Explored bulk inserts, random test data, deletion by employee ID.

**Verified outcome:** Partially achieved — backend decisions and SQL examples done; backend execution not fully completed.

**Why this is strong:** Product + technical judgment in scoping backend approach.

## Episode 4: Mobile access, PWA, and debugging deployment-adjacent setup

**Sources:** S5-3, S5-4, S5-6

**User’s goal:** Access Vite app from physical Android device.

**Unfamiliar problem:** Vite dev server on localhost not reachable from phone; HMR WebSocket failure; LAN timeout.

**User’s actions:**
- Verified Vite bound to localhost only.
- Tested LAN addresses.
- Tried ngrok (failed), LocalTunnel (succeeded).
- Updated `vite.config.ts` with `allowedHosts: ['.loca.lt']`.
- Used LocalTunnel script: `lt --port 3001 --subdomain my-canteen-app`.
- Validated mobile access by opening URL on Android device.

**PWA work:**
- CRA + `react-scripts`; `react-native-svg`; manifest; service worker.
- SWC plugin over Babel.
- Minimal PWA config.
- Global CSS modernization: variables, dark mode, `@layer`, safe-area insets, OKLCH with fallbacks.

**Verified outcome:** Mobile access achieved via LocalTunnel; app loaded on Android. PWA compilation partially verified.

**Unresolved:** Production deployment, full PWA installability/offline, final visual validation.

## Episode 5: Android native build struggles

**Source:** S5-2

**User’s goal:** Build React Native app on Android emulator.

**Unfamiliar problem:** NDK r27.1.12297006, React Native TurboModule registration, Kotlin daemon OOM, C++ linker errors.

**User’s actions:**
- Installed JDK 17, Android Studio/SDK, AVD.
- Fixed `ANDROID_HOME`, `ANDROID_SDK_ROOT`, PATH.
- Tuned Gradle memory to 1 GB, Kotlin daemon to 1 GB.

**Outcome:** Toolchain configured; Android build not successful; C++ linker error unresolved.

**Why it matters:** Strong systems thinking and environment debugging, but unresolved.
