## Day Archetypes — Plain-English Definitions

Each describes *what the price did on a single day*. All measured against the day's open, range, and close.

| Label | What it looks like | How to spot |
|---|---|---|
| **gap_and_hold_up** | Opened with a gap up, kept rallying all day | Open >> prior close, close > open, body confirms gap |
| **gap_and_hold_down** | Opened with a gap down, kept selling off | Open << prior close, close < open |
| **gap_and_fade** | Big gap at open, but the rest of the day retraced it | Big gap, but close back near open |
| **all_day_trend** | One-way move, no pullback | High efficiency (>50%), high trendiness score (≥4/5) |
| **whipsaw_two_sided** | Violent up-and-down, ends near where it started | High whipsaw score (≥4/5) — both sides got hurt |

| **range_bound** | Stayed in a tight zone all day, no momentum | Low efficiency (<30%) |
| **mixed_regime** | None of the above cleanly — the "default" bucket | Catch-all |

## Decision Helpers — "If You See X, Then Y" Cards

20 of these in the dashboard (`Decision Helper` tab). Each is built from the **playbook** — a historical lookup of the form:

> **IF** (phase, day-type-so-far, current window)
> **THEN** next window direction has historically been UP 67% of the time, with n=18 observations

### Example card from your data:

```
IF: BRENT • Phase 1 (full-scale war) • day=all_day_trend • window=us_open
THEN: next window us_open → UP 67% [12 of 18 days]
📊 base rate: n=18
```

### How to read:

- **n** = how many historical days match this exact situation. n=5 is OK, n=20+ is solid.
- **bias %** = historical frequency of the direction. 67% UP doesn't mean "67% chance" — it means "in 12 of 18 comparable sessions, the next window closed up."
- **LOW-CONFIDENCE badge** = n<5. Take with a grain of salt.
- **Phase matters most** — a 67% pattern in Phase 1 (war) tells you nothing about Phase 2 (post-ceasefire).

### What it's NOT:

- Not a prediction. The future is not the past.
- Not a position size. You'd still need stops/targets (see CRITICAL_REVIEW.md).
- Not a complete signal. You need to combine with current news to know which phase you're in TODAY.

### Quick start for using them:

1. **Today**: Look at the dashboard's Phase Timeline tab → identify the current phase (probably still Phase 6).
2. **Today's setup**: Find your day-type (e.g., morning gap up, all-day trend so far).
3. **Look up**: Go to Decision Helper tab → filter by your phase + day-type → see what historically happened next.
4. **Cross-check**: Top window tab → check the window's historical UP/DOWN/FLAT mix.
5. **Confirm**: Cross-factor tab → is it EIA Wed? Monday? OPEC day? Apply those overlays.
6. **Size**: Use your own risk management. The playbook gives *probability*, not *position*.

The cards are the *most actionable* artifact in the project — they translate "Brent moved 67% UP in war-phase all-day-trend sessions" into "if today looks like that, lean long."

## CLAUDE — 2026-07-21T12:04:27.254Z

No, "current window" is not "where the day classifies up to that point" — it's literally the **time-of-day bucket you're currently in** (in IST).

## The 10 windows are clock time, not price action

| Window | IST time | What's happening |
|---|---|---|
| `asia_early` | 01:30–03:30 | CME settlement halt |
| `us_late` | 00:00–01:30 | After-hours US |
| `global_reopen_pre_mcx` | 03:30–09:00 | Asian + European pre-market |
| `mcx_open_drive` | 09:00–10:30 | MCX opens |
| `india_morning` | 10:30–12:30 | India mid-morning |
| `india_midday` | 12:30–15:30 | India lunch / Europe pre-open |
| `europe_midday` | 15:30–18:00 | London open |
| `us_pre_open` | 18:00–20:00 | NY pre-market |
| `us_open` | 20:00–23:00 | NY main session |
| `mcx_tail` | 23:00–00:00 | MCX closing |

## So the card reads:

> **IF** it's currently 8pm IST (`us_open` window), and the day has been an `all_day_trend`, and we're in Phase 1 (war)...
> **THEN** historically, the 11pm-midnight window (`mcx_tail`) closed UP 67% of the time

The playbook is a **time-of-day pattern** within a day, conditioned on phase + day-type-so-far. So to use it:

1. **Look at the clock** (in IST).
2. **Identify your current window** (e.g., it's 7:30pm → you're in `us_pre_open`).
3. **Look up the card** for that window + your phase + your day-type-so-far.
4. **The card tells you** what price typically does in the *next* window (e.g., the us_open session).

The "next_window" is just the chronologically following time bucket on the same day, not a forecast of price direction — it's the *target session* of the historical pattern.

So the answer to your question: **day-type is a "so-far" label** (how the day has behaved up to now), but **window is purely a clock-time label** (which 1.5-3 hour IST bucket you're in right now). The two are independent axes.

**Python f-strings use `{}` for interpolation**, so any `{` or `}` in the JavaScript that should be **literal** in the output must be **escaped as `{{` and `}}`** in the Python f-string.

## Errors I've been hitting:

| Error | Cause |
|-------|-------|

| `invalid syntax. Perhaps you forgot a comma?` | Unescaped `}` breaking f-string parsing |
| `invalid syntax` | Unescaped braces breaking f-string parsing |

## Root cause:

JavaScript has lots of `{}` that must be **literal** in output:
```javascript
// JS template literal - ${intensity} should stay as-is in output
return `rgba(247,129,102,${intensity})`;

// JS arrow function with object
backgroundColor: (ctx) => {{ return `rgba(...)`; }}

// Chart.js config objects
options: {{ plugins: {{legend: {display:false}}}}  // nested objects
```

In Python f-string, these must be escaped:
```python
# Correct escaping:
return f"return `rgba(247,129,102,{{intensity}}`;"
options: {{ plugins: {{legend: {{display:false}}}}, ... }}
```
