# Evidence Extraction: Figma-to-PWA with Supabase Backend

## 1. Problem, Goal, Ambiguity, Constraints

### Primary Goal
Build a working PWA that renders Figma designs as interactive, responsive React components, paired with a backend for internal office order management.

### Frontend Constraints
- **Raw Figma JSON export** wrapped in `.docx` file with structural issues:
  - Flattened layers needing restoration
  - Missing text styles
  - Broken image references
  - Incorrect constraint definitions
  - Scroll behavior not properly encoded
  - Invisible layers that should be removed
  - Inconsistent color formatting
- **File size**: >25 MB JSON too large to paste into chat or online editors
- **Existing renderer**: Used absolute positioning (`absoluteBoundingBox`) causing element overlap on resize
- **Need**: Both cleaned JSON file and responsive renderer producing mobile-ready layouts

### Backend Scope Evolution
- **Initial vision**: Carbon-credit public application with users, journeys, CO₂ credits, wallet system
- **Refined scope**: Internal office order-management tool (McDonald's kitchen display system for employees)
- **Final requirements**:
  - Employee login
  - Menu management
  - Order placement
  - Staff status updates (pending→preparing→ready→delivered)
  - Payment tracking (cash/UPI/card)
  - Outstanding balance calculation per user
- **Explicitly excluded**: Public analytics and notifications from MVP

### Environment Constraints
- **OS**: Windows using VS Code and PowerShell
- **Drive space**: Limited C drive space
- **Node.js**: Absent from `C:\Program Files\nodejs` (`node -v` and `npm -v` returned `CommandNotFoundException`)
- **Migration desire**: Flexible architecture for future Supabase → MERN stack migration
- **Knowledge gaps**: Understanding differences between JSON, JSX, TSX; frontend vs backend engineering mindset; complete deployment pipeline

## 2. User Reasoning, Questions, Decisions, Actions

### Frontend Decisions
- **Single JSON + `screenIndex` prop** over split JSON files for maintainability
- **Flex/grid renderer** using `layoutMode`, `constraints`, `__responsive` instead of absolute positioning
- **Fetch `figma-fix.json` from `/public`** instead of import to avoid bundler issues with large files
- **Plain JavaScript (JSX)** over TypeScript for initial prototyping to reduce complexity

### Backend Decisions
- **Supabase (PostgreSQL)** over MERN (MongoDB + Express) for relational transactional data with ACID guarantees
- **Integer cents** for monetary values to eliminate floating-point precision errors
- **Transactional order creation** using BEGIN/COMMIT/ROLLBACK to prevent partial states
- **Parameterized queries** (`$1`, `$2`) throughout to prevent SQL injection

### Environment Decisions
- **StackBlitz** over local Vite when Node.js unavailable on Windows machine
- **CodeSandbox Containers mode** rejected due to limited free quota

### User Actions
- Shared existing `renderer.jsx` file for rewriting
- Tested renderer in CodeSandbox, encountering and diagnosing multiple errors
- Evaluated portable Node options and D drive installation before pivoting to StackBlitz
- Requested step-by-step walkthrough for Vite + React local setup

## 3. Tools, Technologies, Concepts, Integrations

### Frontend Stack
- **Figma JSON**: Raw design export requiring 10 structural fixes
- **React**: Component-based rendering with hooks (`useMemo`, `useEffect`, `useState`)
- **CodeSandbox**: Initial testing environment
- **StackBlitz**: Recommended alternative using WebContainers
- **Vite**: Local development alternative
- **CSS Flexbox/Grid**: Layout mapping from Figma primitives

### Backend Stack
- **PostgreSQL**: Relational database with `BIGSERIAL` primary keys, `created_at` timestamps
- **Node.js + Express**: API server framework
- **Supabase**: Managed PostgreSQL with built-in authentication and auto-generated REST API
- **JWT**: Token-based authentication
- **pg.Pool**: PostgreSQL connection pooling
- **Materialize view `user_balances`**: Aggregates total orders minus paid amounts per user

### Deployment Architecture
- **Vercel**: Frontend hosting (React PWA with manifest and service worker)
- **Supabase**: Backend (PostgreSQL + Auth + REST API)
- **Render/Heroku/Railway/DigitalOcean**: Alternative backend deployment options

### Key Concepts
- **Figma layout primitives**: `layoutMode` (HORIZONTAL/VERTICAL), `layoutAlign`/`layoutGrow`, `__responsive.size`, constraints
- **CSS mappings**: `layoutMode` → `flexDirection`, `layoutAlign`/`layoutGrow` → `alignSelf`/`flexGrow`
- **Monetary storage**: Integer cents to prevent floating-point errors
- **API contract stability**: Consistent request/response shapes enabling backend migration

## 4. Debugging, Experiments, Failures, Root Causes

### CodeSandbox Errors (Systematically Diagnosed)
1. **`ModuleNotFoundError` for `./FigmaRenderer` and `./figma-fix.json`**
   - **Root cause**: File placement—files needed in `/src` directory with matching extensions (`.jsx`)
   - **Fix**: Proper file placement and extension matching

2. **`ReferenceError: useMemo is not defined`**
   - **Root cause**: Missing `import React, { useMemo, useEffect, useState } from "react"` statement
   - **Fix**: Added proper React hooks import

3. **`figma-fix.json not found`**
   - **Root cause**: File location issue
   - **Fix**: Moved file to `/src` directory or used fetch from `/public`

4. **Slow loading times**
   - **Root cause**: Recursive rendering of entire JSON tree
   - **Fix**: Proposed lighter renderer with `screenIndex` prop to render one screen at a time

### Environment Setup Failure
- **Issue**: `node -v` and `npm -v` returned `CommandNotFoundException` in PowerShell
- **Root cause**: Node.js absent from `C:\Program Files\nodejs`
- **Resolution**: Pivoted to StackBlitz as browser-based alternative

## 7. Dependencies, Trade-offs, Claims Requiring Verification

### Key Trade-offs
- **Single JSON + `screenIndex`** vs split JSON: Maintainability vs complexity
- **Fetch from `/public`** vs import: Async loading vs synchronous import
- **Supabase** vs custom MERN: Speed and managed services vs flexibility and control
- **Plain JavaScript** vs TypeScript: Reduced initial complexity vs type safety
- **StackBlitz** vs local Vite: Zero-setup vs fastest hot-reload experience
