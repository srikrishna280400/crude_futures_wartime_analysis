**1. Problem & Goal**  
- **Problem:** Convert a Figma‑designed screen (JSON‑encoded geometry, colors, text, base‑64 images) into a working, responsive web application without manually recreating every visual element.  
- **Goal:** Build a PWA‑compatible React app that renders the design faithfully, supports different viewports, and can be temporarily exposed via a public HTTPS URL for mobile testing.  

**2. Ambiguities & Constraints**  
- Uncertainty whether the JSON schema (`layers` vs `screen.elements`) matches the intended renderer.  
- Unclear import strategy (direct `src/` import vs `public/` fetch).  
- Initial React‑Native implementation was incompatible with a browser runtime (no `node‑fetch`, no `fs`).  
- Need to debug a Windows PowerShell environment where `node`/`npm` appeared unavailable.  
- Visual fidelity broke on non‑reference viewports (overlap/overflow) → required absolute positioning and viewport scaling.  
- Local Vite server (`localhost`) could not be accessed directly from a phone → required a temporary public HTTPS endpoint.

- **Initial failure:** JSON/runtime mismatches in React‑Native; JSFiddle could not use `node-fetch`/`fs`.  
- **Environment fix:** Fresh PowerShell session → `node -v` succeeded; `npm install` completed (30 packages, 12 low‑moderate vulnerabilities).  
- **Rendering issues:** Decomposed stack (React mount, JSON availability, CSS, scaling, image URLs); used red borders and placeholder to isolate cause.  
- **Public access:** First tunnel registration succeeded (QUIC) but returned 403; resolved by `--http-host-header localhost` (or `--origin-request-host localhost`).  
- **Validation:** PowerShell `HEAD` request returned `200 OK`, `text/html`, `Access-Control-Allow-Origin: *`, `CF-Cache-Status: DYNAMIC`.

**8. Dependencies & Trade‑offs**  

- **Dependency:** Vite + React → lightweight dev server, easy PWA setup; trade‑off: still requires Node.js runtime.  
- **Trade‑off:** Absolute positioning preserves fidelity but may be less semantic than flexbox; user accepted this for visual accuracy.  
- **Trade‑off:** Direct JSON import simplifies asset handling but couples layout to bundle size; alternative (`public/` fetch) would allow runtime updates but adds complexity.  
- **Trade‑off:** Cloudflare Tunnel provides quick public HTTPS but is temporary and depends on both Vite and `cloudflared` staying running.
